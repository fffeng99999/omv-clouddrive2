# omv-clouddrive2

An [OpenMediaVault](https://www.openmediavault.org/) 8.x plugin that runs
[CloudDrive2](https://github.com/cloud-fs/cloud-fs.github.io) — a cloud-drive
aggregation and FUSE mount service — as an OpenMediaVault managed service.

Debian package name: `openmediavault-clouddrive2`

Versioning: the plugin's major version follows the OpenMediaVault major version
(OMV 8.x → plugin `8.x.y`).

## Features

Single page under **Services → CloudDrive2**.

**Status** (read-only)

- Service status (`Running` / `Stopped`)
- Installed CloudDrive2 version
- Web interface port — fixed at `19798`
- Update status and latest upstream version

**Settings**

- **Enabled** – start the service at boot (Save, then Apply to take effect)
- **Configuration directory** – `CLOUDDRIVE_HOME`; must be located on a mounted
  filesystem
- **Update channel** – `stable` (official releases) or `preview` (beta releases)

**Actions**

- `Save` / `Apply` – write the OMV configuration database and deploy the systemd unit
- `Start` / `Stop` / `Restart` – immediate service control
- `Check for updates` – query the upstream GitHub releases for the selected channel
- `Update` – download the selected channel's release for the host architecture,
  replace the bundled core and restart the service (configuration and data are kept)
- `Open UI` – jump to the CloudDrive2 web interface on port 19798

> **Scope**: the plugin only performs the OpenMediaVault side integration — enable
> at boot, start/stop/restart, data directory, self-update and status display.
> CloudDrive2 accounts, cloud drives and mount points are configured in
> CloudDrive2's own web interface on port 19798, and are never touched by the plugin.

Internationalization: Simplified (`zh_CN`) and Traditional (`zh_TW`) Chinese catalogs
are shipped. When the system language is Chinese, the navigation entry
(**Services → CloudDrive2**) and every web interface label are translated. Add more
languages by dropping a `<locale>/openmediavault-clouddrive2.po` file under
`usr/share/openmediavault/locale/`.

Access control: the navigation entry and every RPC method require the `admin` role.

## Architecture

- The CloudDrive2 core is closed source and is **bundled per architecture**. At build
  time `build-deb.sh` downloads the upstream release archive and stages it under
  `opt/clouddrive2/` (the `clouddrive` binary, the `wwwroot/` web assets and a
  `VERSION` file). No upstream artifact is committed to this repository.
- The systemd unit `clouddrive2.service` is generated by the OMV Salt state
  (`/srv/salt/omv/deploy/clouddrive2/`) — never edited by hand.
- `CLOUDDRIVE_HOME` is exported from the *Configuration directory* setting.
- Configuration is stored in the OMV database as `conf.service.clouddrive2`; the RPC
  service name is `CloudDrive2`.
- Mount points use `fusermount3`, hence `Depends: fuse3`.

## Installation

1. Download `openmediavault-clouddrive2_<version>_<arch>.deb` from the latest
   [GitHub Release](https://github.com/fffeng99999/omv-clouddrive2/releases)
   (or build it yourself, see below).
2. Install it via CLI on the NAS:

   ```bash
   apt install ./openmediavault-clouddrive2_8.0.3_amd64.deb
   ```

3. Open **Services → CloudDrive2**, point *Configuration directory* at a path on a
   mounted filesystem (your data array is the natural choice), tick **Enabled**, then
   click **Save** and **Apply**.
4. Click **Open UI** and configure your cloud drives and mounts in the CloudDrive2
   interface (port 19798).

Uninstall:

```bash
apt purge openmediavault-clouddrive2
```

## Build

Built in the cloud with GitHub Actions
([.github/workflows/build.yml](.github/workflows/build.yml)):

- Push a tag `v*` → build for `amd64`, `arm64` and `armhf`, then create a GitHub
  **Release** with the `.deb` files attached (the tag version must match
  `debian/changelog`).
- `workflow_dispatch` → manual build with a `channel` input (`stable` / `preview`) and
  an optional explicit upstream tag.

Local build (on any Debian-based system, e.g. a container):

```bash
sh ./render-vars.sh                 # render the ${GITHUB_USER} placeholders
./build-deb.sh stable amd64         # download and stage the upstream release
dpkg-buildpackage -us -uc -b -aamd64 -d
```

Upstream release archive used by `build-deb.sh`:
`clouddrive-2-linux-<x86_64|aarch64|armv7>-<version>.tgz`.

## Development notes

- The plugin is pure declarative: a PHP RPC service plus workbench YAML — there is no
  JavaScript/TypeScript build step.
- The author name in `debian/*` and in the source headers is a `${GITHUB_USER}`
  placeholder. `render-vars.sh` renders it from `debian/variables.env`; CI runs the
  script before `dpkg-buildpackage` and refuses to publish a package that still
  contains a placeholder. **Run it before any local build.**
- Cross builds skip `dh_strip` / `dh_dwz` / `dh_shlibdeps` / `dh_makeshlibs` for the
  prebuilt static binary (no cross `objdump` on the runner).
- `.gitattributes` forces LF: a CRLF `postinst` breaks package installation.
- Quick debugging without packaging: copy the files to the matching paths on a test
  VM/container, run `omv-mkworkbench all` and restart `omv-engined`.
- **Never install untested builds on a production NAS** — use a VM or container first.
